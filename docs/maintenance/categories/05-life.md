# 🕊️ 定期人壽 (Term Life) 維護手冊 (05-life)

> **定位宗旨**：專門收錄純消費型、極高身故槓桿、0% 儲蓄成分嘅定期人壽保險（共 14 款）。為家庭頂樑柱提供堅實後盾！新手 Agent 30 秒秒懂維護心法！⚡

---

## 🎯 類別定位與維護核心心法

1. **「純身故槓桿，0% 保費回贈 (0% ROP)」鐵律**：
   - 定期人壽（Term Life）係純消費型保險：**「保費全部用嚟買身故保額，零儲蓄成份、期滿在生零現金價值（0% Return of Premium）」**！
   - 千祈唔好同「儲蓄人壽」、「分紅險」或「可退保費險 (ROP)」混淆！任何寫有保證回本、紅利派發嘅字眼喺定期壽險都係嚴重錯誤！
2. **定額身故賠償（Sum Assured 100%）**：
   - 受保人於保障期內因疾病或意外不幸離世，保司**一筆過賠償 100% 投保額（Sum Assured）**畀指定受益人。
   - 保額通常以百萬甚至千萬港元計（如 HK$1,000,000 至 HK$20,000,000）。
3. **自殺不保條款（Suicide Clause）**：
   - 業界標準條款：**「保單生效日或復效日起 1 年（少數為 2 年）內自殺，不承擔身故賠償責任，保司僅無息退還已繳保費」**。
   - 滿 1 年或 2 年後自殺則照常受保。
4. **平準保費 (Level Premium) 與保證續保權 (Guaranteed Renewability)**：
   - 保障期多為：1 年續保（每年隨年齡加費）、5 年、10 年、20 年期平準保費（指定期內保費鎖定不變）。
   - 保證續保至 80 歲、85 歲或 100 歲，**續保時無須重新申報健康狀況或重新體檢**。
5. **末期疾病預支賠償（Terminal Illness Advance Benefit）**：
   - 絕大多數優質定期壽險附送：若被專科醫生確診預期壽命少於 12 個月，可**預先提領 100% 身故保額**應急，提領後保單即告終止。
6. **吸煙與非吸煙保費天與地**：
   - 定期人壽按「非吸煙者（Non-Smoker）」與「吸煙者（Smoker）」嚴格定價，吸煙者保費往往貴 50% 至 100%！

## 🛠️ 常規更新步驟 (Step-by-Step SOP)

### 1. 遇到保費變更點改？
1. 開啟 `public/data/insurance-data.json`。
2. 搜尋對應人壽產品 ID（例如 `"id": "life-bowtie"`）。
3. 檢查並更新：
   - `premium_range`：確認非吸煙者 30 歲男/女基本保費示例（例如：`以30歲非吸煙男性投保HK$1,000,000保額計算，每年保費約數百元至千餘元`）。
   - `premium_notes`：註明「吸煙習慣對保費有顯著影響；定期人壽不設儲蓄成份及退保現金價值」。
   - `premium_available`：確認為 `true`。

### 2. 遇到保險公司更新 PDF 條款點換？
1. 下載官方最新定期壽險產品小冊子或保單條款 PDF。
2. 存入 `public/docs/brochures/`（如：`fwd-myterm-2026.pdf`）。
3. 運行清單雜湊註冊：
   ```bash
   node scripts/build_pdf_manifest.mjs
   ```
4. 在 `insurance-data.json` 中更新該產品之 `coverage` 與 `citations`：
   - 身故賠償項目之 `source_url`、`page` 及 `quote`，確保有原文頁碼作佐證。

### 3. 邊啲常見誤區千祈唔好踩？⚠️
- ❌ **誤區一：誤寫「保費回贈 (ROP)」或「保單現金價值」！**
  - 定期人壽**絕無現金價值**！受保人期滿健在係**無錢退**嘅！千祈唔好手多寫「儲蓄紅利」或「期滿取回保費」，否則會引起嚴重誤導！
- ❌ **誤區二：混淆「末期疾病預支」同「額外贈送」！**
  - 末期疾病保障（Terminal Illness Benefit）係**「預支 (Advance Payment)」**身故保額，唔係額外賠多一份！預支完 100% 後保單立即終止，身故時唔會再賠多一次。
- ❌ **誤區三：漏寫自殺免責條款（Suicide Exclusion）！**
  - 生效日起 1 年（或 2 年）內自殺係**不保**嘅（只退已繳保費）。切忌寫成「任何情況身故均 100% 賠足」。
- ❌ **誤區四：忽略吸煙者保費加幅！**
  - 報價或保費說明若無標明「非吸煙者」，會令吸煙客戶投保時因保費大幅增加而產生爭議。

## 🧪 測試與驗收 Command

完成數據或條款修訂後，務必依序執行以下 5 道把關指令：

```bash
# 1. 檢查 PDF 鏡像清單雜湊（若有變動 PDF）
node scripts/build_pdf_manifest.mjs --check

# 2. 運行單元測試
npm test

# 3. 執行嚴格代碼風格檢查（0 Warning，0 Error）
npm run lint -- --max-warnings=0

# 4. 驗證篩選器邏輯與邊界情景
npm run test:filters

# 5. 生產構建驗證
npm run build
```

🚀 5 項檢查綠燈通過，即可放心出 PR！
