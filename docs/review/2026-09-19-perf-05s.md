### Data path

| Asset | Raw | Gzip (measured) |
|---|---:|---:|

- Browser preload starts the transfer as soon as HTML head is parsed.
- Provider uses a **module-level single-flight** `fetch` promise: remounts/HMR retries do not re-download unless the first fetch failed.
- `parseInsuranceData` still runs once per successful snapshot (evidence validation unchanged).
- **Not split by category** in this PR: product IDs, compare tray, search, and PDF evidence all assume one validated snapshot. Splitting is possible later but needs a data contract review.
- Hosting: this site already ships via Cloudflare (Pages/Workers assets). Cloudflare serves gzip/brotli for JSON/JS/CSS at the edge; local `gzip -c` size is a floor, not a promise of edge encoding.

## What changed (implementation)

1. **`vite.config.ts`** — `manualChunks` for `vendor-react`, `vendor-router`, `vendor-framer`, `vendor-gsap`, `vendor-lenis`, `vendor-radix`, `vendor-lucide`, `vendor-recharts`, `pdfjs`.
2. **`src/App.tsx`** — `Home` is `lazy()` like every other page; shell is Layout + providers only.
3. **`src/components/Layout.tsx`** — removed static `gsap`/`lenis` imports; both load via dynamic `import()` after `requestIdleCallback`; `SearchPalette` idle-lazy; `RoutePrefetch` mounted.
4. **`src/providers/InsuranceDataProvider.tsx`** — no static GSAP; shared JSON promise; ScrollTrigger refresh only after dynamic import.
5. **`src/pages/Home.tsx`** — critical path is Hero; marquee/grid/method/promises/CTA/toast are lazy sections.
6. **`src/pages/home/Hero.tsx`** — `ParticleField` is decorative `lazy()` + Suspense.
7. **`src/lib/route-prefetch.ts` + `RoutePrefetch`** — idle warmup for `/categories`, `/compare`, `/insurers`; hover warmup on internal links. **Does not** refetch `insurance-data.json`.
8. **`index.html`** — paper background critical CSS, `theme-color`, data preload, non-blocking Google Fonts.

## Honest assessment of “~0.5s”

| Scenario | Realistic expectation |
|---|---|
| Warm cache, desktop, broadband, SPA click to prefetched route | **Shell paint often ≪ 0.5s** (chunk already warm; data already in memory). |
| Cold first visit, desktop, broadband | **Shell chrome can approach 0.5s** on a fast connection once HTML+CSS+react/framer arrive in parallel; **not guaranteed**. |
| Cold first visit + full home content + JSON parse + CJK fonts | Often **> 0.5s** to complete content paint; fonts swap later. |
| Cold mobile / high RTT / slow CPU | **0.5s is not a promise.** JSON alone is ~290 kB gzip + parse of 158 products. |
| `/category/:id` after idle warmup | Route chunk small; shell already up — **perceived switch feels instant** relative to old monolith. |

**Limits this PR does not remove**

- `framer-motion` remains on the shell critical path (Navbar + route transitions + progress bar). Removing it would be a UX rewrite, not a chunk tweak.
- Insurance snapshot is still monolithic; evidence integrity beats premature split.
- PDF worker (~1.2 MB) stays out of the shell (already lazy) but first open of a PDF is heavy.
- No automated Lab CI FCP gate in this PR; numbers above are build-output evidence + method notes.
- Another agent’s insurers redesign work is **not** in this branch (isolated worktree); merge order may reintroduce page weight on `/insurers`.
