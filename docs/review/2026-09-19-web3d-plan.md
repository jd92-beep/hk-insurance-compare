## 1. Phase A — stronger CSS 3D, no new deps (ship fully)

Goal: every major card reads as layered paper (resting depth) and lifts/tilts on fine-pointer hover, without new packages and without breaking hit-testing, keyboard focus, print, or reduced-motion.

### A1. TiltCard micro-enhancements (same file, no API break)

Keep the public props `{ children, className, max, glare, perspective }`. Optional additive props only if needed:

```ts
// optional, default preserves current behavior
lift?: boolean          // apply --depth-lift-hover translate on the face when enabled
dataDepth?: string      // e.g. "product" | "insurer" | "category" | "guide" | "hero"
```

If `lift` is omitted, **do not** add face translate — cards that already have `hover:-translate-y-*` stay as-is; avoid double lift.

Prefer: **stop using Tailwind `hover:-translate-y-*` on cards that sit inside TiltCard**, because a CSS transform on the same element that framer animates can fight. Pattern:

- Outer: `TiltCard` (perspective + rotate).
- Inner article/link: `depth-card` or `depth-surface` **without** `hover:-translate-y-*` when tilt is on.
- Cards **without** TiltCard keep `hover:-translate-y-1` + `depth-card` (CSS-only depth).

## 2. Phase B — optional three.js slice (only if time; not required for “more 立體”)

### B1. Scope decision (narrow)

**Allowed slice:** one decorative jewel / paper-stack micro-scene on the **Hero**, OR a single shared “depth preview” canvas — **not** a WebGL UI framework, **not** restoring removed large WebGL rings, **not** replacing ProductCard DOM with meshes (comparison content must stay real DOM text for a11y, SEO, evidence chips).

Preferred technical approach if Phase B is attempted:

- Keep `projectGem` as the **single geometry source**. A three.js mesh is a realtime renderer of the same vertices — do not invent a second geometry definition.
- Do **not** pull `@react-three/drei` unless needed; raw `three` + a thin component is smaller.
- Alternative cheaper path already in-repo: upgrade `ParticleField` gem atlas resolution / add a single large jewel canvas — **zero new deps**. Prefer this before adding three.js.

### B2. Architecture (if adding three.js)

```
src/components/fx/depth/
  JewelCanvas.tsx     // default export; React 19 + useEffect
  jewel-scene.ts      // pure three setup/teardown; no React
  budget.ts           // dpr/pixel/particle guards (mirror motion-runtime)
```

Lazy load pattern (same as ParticleField):

```tsx
const JewelCanvas = lazy(() => import("@/components/fx/depth/JewelCanvas"));
// Hero.tsx
{!reduced && (
  <Suspense fallback={null}>
    <JewelCanvas className="pointer-events-none absolute …" density={0.6} />
  </Suspense>
)}
```

Gate mount:

```ts
const enabled =
  !reduced &&
  !coarse &&                         // pointer: coarse
  !document.hidden &&
  matchMedia("(hover: hover) and (pointer: fine)").matches;
```

### B3. Budget (hard caps — assert in a unit test if Phase B lands)

| Guard | Value |
| --- | --- |
| `devicePixelRatio` | `Math.min(devicePixelRatio, 1.5)` |
| Canvas pixels | ≤ `1_200_000` (stricter than ParticleField’s 2M — three is heavier) |
| Geometry | ≤ 40 triangles (reuse gem ≈ 33 faces) |
| Materials | 1 material, vertex-colors or flat MeshLambert; no env maps, no postprocessing |
| Lights | 1 directional + 1 ambient |
| Frame loop | reuse `createFrameLoop`; stop on `IntersectionObserver` out / `visibilitychange` / reduced-motion |
| Dispose | `geometry.dispose()`, `material.dispose()`, `renderer.dispose()`, `forceContextLoss()` on unmount |
| Bundle | dynamic `import("three")` only; add `manualChunks` entry `vendor-three` in `vite.config.ts` if three is installed |
| Interaction | pointer parallax only; **no** OrbitControls; no touch drag capture |

3. Forbidden: replacing `index.html` with a three.js playground, or adding a second Vite multi-page entry without verifying SPA routing still resolves.

- Work offline for Phase A CSS part.
- If CDN three fails, show CSS-only cards (graceful).

## 5. Acceptance — what “更多 立體” means (visual contract)

Ship Phase A when **all** of the following are true on a fine-pointer desktop browser (state browser/version), and the reduced-motion / coarse-pointer path still shows **static layered depth** without tilt:

1. **Resting depth (no hover)**  
   Every major card shows at least: light top edge, a mid contact shadow, and a soft long shadow — readable as “paper on paper,” not a flat border.

2. **Hover lift**  
   Cards rise ~6px (category/index ~8–10px) with a longer, softer shadow. Lift eases in ~0.3–0.35s `cubic-bezier(0.22, 1, 0.36, 1)`.

3. **Perspective tilt (fine pointer only)**  
   - Product / insurer / guide cards: subtle rotate, max effective ~3–4° visual after spring.  
   - Category cards: slightly stronger (~6° request; `tiltAt` hard-clamps at 7°).  
   - Hero art: strongest, stamp visibly closer than illustration (existing `translateZ(70px)`).  
   Tilt never fires on `pointer: coarse`, `prefers-reduced-motion`, or while focus is inside the card.

4. **Layering / Z cues**  
   - Category color bars and icons sit “above” the card face when tilted.  
   - Insurer category chips look like raised tokens (`chip-3d`).  
   - Hero stamp / MethodStory stamp float above their paper stack.  
   - Text and buttons remain **flat** for legibility and hit accuracy.

5. **Scene depth (home)**  
   MethodStory stage cards at different `translateZ` show differential parallax as the stage moves; marquee keeps its slight `rotateX` ribbon feel.

6. **Negative acceptance (must NOT)**  
   - No WebGL required to perceive depth.  
   - No layout shift on keyboard focus.  
   - No meaning conveyed only by motion/shadow.  
   - Compare/evidence/provenance copy unchanged.  
   - Site still builds with stock `index.html`; demo (if any) is extra.
