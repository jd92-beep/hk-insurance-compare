# 03 — Next Phases

Suggested roadmap, in priority order. Each phase is independently shippable.

## Phase 1 — Deploy & verify in production (small)
- Pick hosting (GitHub Pages / Vercel / Cloudflare Pages). If GitHub Pages: set `base` in `vite.config.ts` to `/hk-insurance-compare/` and add a SPA 404 fallback (`404.html` copy of `index.html`).
- Add GitHub Actions: `npm ci && npm run build` on push; deploy on master.
- Smoke-test all routes after deploy (`/`, `/category/medical`, `/product/medical-avo`, `/compare`, `/vhis`).

## Phase 2 — Flexi plan depth (the big data win)
- Extract per-level benefit limits and premiums from official flexi PlanDoc / StandardPremium PDFs (URLs already in `vhis-plans.json`, all verified 200).
- Suggested approach: extend `scripts/build_vhis.py` (or new `scripts/extract_flexi.py`) with PDF text extraction (pypdf in a venv — a ready venv exists at `/tmp/vhis-venv` but is ephemeral; recreate with `python3 -m venv`), focusing first on the ~10 most popular flexi products (Bowtie F00031/F00060, AIA F00022, Bupa F00035/F00040, Cigna F00016…).
- Target schema: add optional structured fields (e.g. `flexi_plans: [{cert, name_zh, levels, annual_limits, deductibles, premiums_by_age}]`) rather than overloading prose fields. Update `src/types/insurance.ts` accordingly.
- Keep citations honest: every extracted number needs its PDF + page + quote.

## Phase 3 — Structured premiums (data model cleanup)
- Replace the prose `premium_notes` age curve with a structured field (e.g. `standard_premium_by_age: [{age, male, female}]`) generated by `build_vhis.py`; simplify `parsePremiumCurve` to read it. Keep prose for backward compat or migrate all readers.

## Phase 4 — Performance
- Route-level code-splitting (`React.lazy` per page) + `manualChunks` for vendor libs; target < 300 KB initial JS.
- Consider generating static JSON per category/product if the 101-product bundle grows.

## Phase 5 — Quality gates
- Fix the 22 pre-existing lint errors (or consciously suppress with comments).
- Add minimal tests: pure helpers (`vhis-utils.ts`, `canonical-benefits.ts`, `lib/categories.ts` premium parsing) with vitest.
- CI: build + lint + a data-validation script (JSON schema check, cert numbers vs official CSV, link spot-checks).

## Phase 6 — Freshness automation
- Scheduled job (GitHub Actions cron) running `build_vhis.py`; open a PR when the official registry changes.
- Surface "名單最後更新" from `fetched_at` (already shown on `/vhis`).

## Phase 7 — Non-medical categories refresh
- Other 8 categories are snapshots from 2026-08-09 manual research; consider the same official-source treatment where public data exists (e.g. 保監局 registers). Also investigate the stray `"Blue"` insurer key.
